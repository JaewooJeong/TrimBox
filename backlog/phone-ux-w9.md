# 폰 UX 라운드 (W9, 2026-09-20)

실제 웹 빌드 스크린샷(390×844, 360×640, 844×390)으로 확인한 결과, 폰에서 "깨지지 않고 동작"은 하지만
"폰용으로 설계"된 상태는 아니었다. 최종 타깃이 Android 이므로 실기기 확인 전에 폰 UX 를 먼저 맞춘다.
사용자 결정(2026-09-20): 장비 선택은 전체 화면 페이지로, 폰에서는 라벨 기본 숨김.

## 3. 설계

### 3.1 라벨 (렌더러, `LabelPolicy.compact`)
- 순서 배지(파란 원 숫자)는 모든 보이는 짐에 그린다 (기존 비켜 놓기 유지).
- 이름 알약은 다음 짐에만: 선택된 짐, 드래그 중인 짐, 충돌 짐, 테일게이트에 걸린 짐, 그리고 화면에서
  투영 면적이 가장 큰 짐 `compactLabelLimit`(3)개.
- 알약이 이미 놓인 라벨과 겹치면 그리지 않는다 (배지만). `all` 정책은 기존 동작 그대로.
- 알약 글자 11px 유지, 폰에서는 알약 최대 폭 120px.

### 3.2 캡션 (`CaptionStyle.compact`)
- 한 줄: `쏘렌토 5인승 · 109~138×107×79~82cm` (공식 용량·2열 표시 생략), 넘치면 말줄임.
- 상태 알약(테일게이트 OK / 미적재 / 안 닫힘)은 그대로 그 위에.

### 3.3 캔버스가 시트를 따라간다 (폰)
- `DraggableScrollableController` 를 듣고 캔버스 아래 여백 = 현재 시트 높이. 카메라는 `_ensureCamera` 가
  크기 변화에 맞춰 거리를 다시 맞춘다 (각도·줌 비율 유지).
- 시트 스냅: `snap: true`, 스냅 크기 [초기값(28%), 짐 있음 45%]. 최소 0.12(손잡이 + 히어로 줄), 최대 0.85.
  빈 트렁크에 짐이 처음 들어오면 45% 로 올라간다 (`_raiseSheetForContent`) — 남는 캔버스(약 430px)에 트렁크가 꽉 찬다.
- 적재율 카드는 폰에서 한 줄 칩: `적재율 62% · 16개 · 남은 358L`.

### 3.4 선택 도구 띠 (폰, 캔버스 위)
- 짐이 선택되고 드래그 중·스텝 뷰가 아니면 캔버스 아래(캡션 위)에 떠 있는 띠:
  `[색 점] 이름(말줄임) [회전] [삭제] [✕ 선택 해제]`. 버튼 44px.
- 툴팁: '선택한 짐 회전', '선택한 짐 삭제', '선택 해제' (목록 타일의 '90° 회전'·'삭제'와 구분).

### 3.5 폰 시트 구성 (위 → 아래)
1. 손잡이
2. 히어로 줄: `들어갈까?` | `자동 배치` (48px)
3. 도구 줄 한 줄: `+ 박스 추가` | 순서 가이드(아이콘, 순서가 있을 때) | 실행 취소 | 다시 실행 | `⋯`
   (메뉴: 배치 저장, 불러오기, 스크린샷*, 공유 카드* — *파일 I/O 지원 플랫폼만)
4. 상태 두 줄: `박스 16개 · 부피 62% · 남은 높이 2cm` + 상태 행(초록/주황/빨강, 탭하면 상세)
5. 목록 타일 (회전·삭제 48px 탭 영역)
6. 하단 SafeArea 여백
- 빈 상태: 손잡이 → 안내 + `캠핑 장비 선택하기` → `저장된 배치 불러오기` 텍스트 버튼. 도구 줄 없음.
- 데스크톱 고정 패널·폰 가로 압축 패널은 그대로.

### 3.6 장비 선택 전체 화면 페이지 (폰)
- `showGearPicker(context, fullScreen: true)` → `MaterialPageRoute(fullscreenDialog: true)` 로
  `AddBoxDialog(fullScreen: true)`. 결과 타입·값은 다이얼로그와 같다.
- Scaffold: 앱바(✕ 닫기, 제목 `장비 선택`, 오른쪽 `N개 선택` 칩) → 고정 머리말(카테고리 칩, 서브카테고리 칩,
  검색) → 목록(추천 세트는 목록 맨 위) → 하단 고정 바(`선택 해제` 텍스트 + 전체 폭 `추가 (N개)` 48px, SafeArea).
- `resizeToAvoidBottomInset: true`: 키보드가 올라오면 목록만 줄어들고 머리말·하단 바는 남는다.
- 직접 입력 탭: 입력란은 스크롤 영역, 하단 바의 `추가`.
- 목록 행 최소 48px, 체크박스·수량 버튼 탭 영역 40px 이상.

### 3.7 판정·자동배치 결과 (폰: 아래 시트)
- `_presentResult`: 데스크톱은 기존 `AlertDialog` 그대로(픽셀 동일), 폰은
  `showModalBottomSheet(isScrollControlled: true)` + `resultSheetBody`: 둥근 위 모서리, 손잡이,
  제목 행(오른쪽 ✕ '닫기'), 스크롤 내용, 버튼은 전체 폭 세로 스택 — 보조(초록 외곽선) 위, 주 동작(파랑 48px)
  맨 아래(엄지에 가장 가깝게). `확인`/`닫기` 텍스트 버튼은 없고 ✕·스크림 탭·아래로 끌기로 닫는다. 하단 SafeArea.
- 모두 적재: 보조 `순서 가이드`(순서가 2개 이상일 때) → 주 `배치 저장`.
- 일부 적재: 보조 `2열 +Ncm 적용`(있을 때) → 주 `다시 배치`.
- 적재 불가: 보조 `2열 +Ncm 적용`(있을 때) → 주 `확인`.
- 자동 배치 대안(전략 3종)도 폰에서는 아래 시트: 카드 전체 폭, `이 배치 적용` 전체 폭.

### 3.8 SafeArea·터치
- 본문은 `SafeArea(top: false)` 로 좌우·하단 인셋 반영. 시트는 화면 바닥까지 내려가되 안쪽 하단 여백
  = `viewPadding.bottom`. 선택 도구 띠·결과 시트도 같은 여백.
- 터치 폼팩터에서 앱바 `?` 는 키보드 단축키 대신 `조작법`(제스처) 다이얼로그.

## 5. 검증 계획
- 위젯 테스트: 폰 5크기(390×844, 360×800, 360×640, 390×600, 844×390)에서 전 플로우 overflow 0,
  시트 따라가기(캔버스 높이 변화), 선택 도구 띠 동작, 도구 줄·⋯ 메뉴, 장비 페이지(검색·세트·키보드 인셋·뒤로가기),
  결과 시트 버튼(주/보조/닫기, 전체 폭, 간격), SafeArea(viewPadding 시뮬레이션), 빈 상태.
- 렌더러 테스트: compact 정책에서 알약 수 ≤ 선택·문제 짐 + 3, 겹침 0, 배지 수 = 보이는 짐 수.
- Playwright: 모바일 좌표 갱신(위젯 테스트 `getRect` 로 산출), 폰 플로우 추가, 2회 연속 통과,
  데스크톱 32개는 좌표 변경 없이 그대로 통과.
- 독립 리뷰 에이전트가 스크린샷·코드를 보고 UX 문제를 다시 찾는다.

## 6. 결과 (2026-09-20)

### 6.1 구현·검증
- 위젯 테스트 830개(`flutter test`, 약 2.5분): 새로 `simulator_phone_test.dart`(독립 검증 67 + 리뷰 회귀 8),
  `gear_picker_test.dart`(16), `label_policy_test.dart`(14), `caption_style_test.dart`(5). 데스크톱 렌더 스냅샷 22장 md5 동일.
- 브라우저 E2E 34개(`npx playwright test`, 3배치 약 12분): 폰 스펙 10개 재작성(390×844 ×6, 360×640, 844×390 ×2, 태블릿),
  데스크톱 24개는 좌표 무변경. 좌표는 위젯 테스트 `getRect` 로 산출(`e2e/mobile.spec.ts` 머리말).
- 독립 검증이 찾아 고친 것: 시트 목록 타일 버튼 40px → 48px, 앱바 `?` 툴팁이 첫 프레임에 '키보드 단축키' 로 나오던 것
  (`_layout` 을 앱바보다 먼저 정함), 빌드마다 새 `snapSizes` 리스트를 줘서 시트가 안 올라가던 것,
  `ensureVisible` 이 시트 안 목록을 스크롤해 시트 확장을 막던 것(하네스 `expandSheet`).

### 6.2 UX 리뷰(실제 빌드 스크린샷 133장)가 찾은 17건 중 이번에 고친 것
| # | 문제 | 수정 |
|---|---|---|
| 1 높음 | `들어갈까?` 가 화면 배치가 아닌 새로 짠 가상 배치를 판정 — 트렁크가 빨간데 "모두 적재 가능" | 지금 배치를 먼저 판정(`_currentLayoutProblems`): 문제가 있으면 "지금 배치: 문제 N개" + "다시 배치하면 N/M개" + `이 배치 적용`; 문제 없고 다 실렸으면 화면 배치 기준(`_currentLayoutAsResult`); 못 실은 짐만 있으면 재배치 판정 |
| 2 높음 | 패커가 UI 스레드에서 동기 실행, 32개 6~25초 멈춤 | 재시도 횟수를 짐 수로 줄임(16개까지 24, 24개까지 12, 그 위 6; 대안은 그 절반) → 32개 약 1.5~2초. isolate 이관은 남김(아래) |
| 3 높음 | 카테고리·서브카테고리 칩을 누르면 선택이 전부 사라짐 | 선택 유지 (해제는 `선택 해제`로만) |
| 4 높음 | 일부 적재 스낵바가 14줄 글 벽 | 두 항목 + "외 N개" + `자세히`(판정 시트); 같은 이름·사유는 "×N" 으로 묶음 |
| 5 높음 | 받침 삭제 → 위 짐이 휠하우스 속으로 떨어져 빨간 충돌, 알약은 초록; 수동 편집 뒤 추가는 테일게이트를 막는 자리에 얹힘 | `SupportRule.validLevels` 가 휠하우스 부피를 뚫는 층을 빼고, 받칠 곳이 없으면 발밑 가장 높은 것 위에 얹음(`restOnWhateverIsBelow`); 알약이 겹침도 봄("짐 겹침 N개"); 자리 없으면 트렁크 밖에 두고 스낵바 |
| 6 중간 | 못 실은 짐 3D 가 알약·캡션과 겹침 | 폰에서는 흐리게(0.45) 그리고 배지·이름 없음 (완전한 띠 UI 는 남김) |
| 7 중간 | 숫자 불일치(칩 32개 vs 18/32), "(+13)" 이 cm 로 읽힘, 주차 짐을 "충돌 감지" 로 표시 | 칩·상태 줄 "18/32개", "외 N건", 타일 "안 들어감" 태그와 "안 들어감 (트렁크 밖에 둠)" 문구 |
| 8 중간 | 2열로도 안 되는데 "2열을 당겨 보세요" 팁, "더 큰 차량" | 제안이 있을 때만 제안, 없으면 "2열을 당겨도 …" / "장비 크기를 확인하세요" |
| 9 중간 | 도구 띠가 선택한 짐을 덮음 | 선택한 짐이 캔버스 아래 38% 안이면 띠를 위(칩 아래)에 |
| 10 중간 | 순서 배지 "8" 이 "10" 뒤에 가려짐 | 배지만 남았을 때 좌우로도 비켜 놓기(`placeLabelGroup(sideways:)`, 폰만) |
| 11 중간 | 검색이 이름 부분일치뿐 | 카테고리·서브카테고리 이름 + 동의어(쿨러↔아이스박스, helinox↔헬리녹스 …) |
| 12 중간 | "아래로 내리면 트렁크 크게" 가 거짓(폭 기준 맞춤) | 조작법 문구 수정("트렁크만"); 가로 모드는 시트 문구 없음 |
| 13 중간 | 같은 결과 3장을 고르게 함, 0/1 에도 적용 활성 | 같은 결과에 "(= 균형 배치)", 0개면 `이 배치 적용` 비활성 |
| 14 낮음 | 온보딩 문구가 W9 이전 | 터치 조작법 행 갱신(짐을 탭 → 도구 띠) |
| 15 낮음 | 계산 시간 배지, 손잡이 2개, 일부 적재인데 초록 막대 | 폰 시트에서 배지 제거, `showDragHandle: false`, 막대 색 = 판정 색 |
| 16 낮음 | `저장된 배치 불러오기` 36px | 44px (아이콘 36 으로 220px 안에 유지) |
