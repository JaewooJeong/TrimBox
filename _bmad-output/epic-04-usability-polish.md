# Epic 04: 사용성 완성 — 반응형 + 공유 + 온보딩

## 개요

Epic 01~03으로 핵심 시뮬레이션 기능이 완성된 상태에서, **모바일/태블릿 사용성**, **결과 공유**, **첫 사용자 안내**를 보완하여 제품 완성도를 높인다.

**선행 완료:** Epic 01 (MVP) + Epic 02 (카메라/스태킹) + Epic 03 (리얼리티 향상)

**핵심 가치:** "어디서든, 누구나" — 모바일에서도 쾌적하게 쓸 수 있고, 결과를 바로 공유하고, 처음 쓰는 사람도 헤매지 않는다

---

## Story 1: 스크린샷 내보내기 개선 (P0)
**목표:** 기존 스크린샷 기능의 품질과 공유 편의성을 높인다

**현재 상태:** `_takeScreenshot()`이 구현되어 PNG 다운로드가 동작함. 그러나 개선이 필요한 부분이 있음.

**인수 조건 (AC):**
- AC1.1: 스크린샷에 트렁크 정보 워터마크가 포함된다 (차종명 + 짐 개수 + 점유율)
- AC1.2: 스크린샷 해상도 옵션 제공 (1x/2x/3x) — 기본 2x
- AC1.3: 스크린샷 촬영 시 UI 패널, 회전 버튼 등 오버레이가 제외된다
- AC1.4: 모바일 웹에서 "이미지 저장" 또는 "공유" 시트가 열린다 (Web Share API)

**기술 노트:**
- 현재 `RenderRepaintBoundary.toImage(pixelRatio: 2.0)` 사용 중
- 워터마크: 캡처 후 `Canvas`에 텍스트 오버레이 추가
- Web Share API: `navigator.share({ files: [file] })` — 미지원 브라우저는 기존 다운로드 폴백
- `_canvasKey`의 `RepaintBoundary`에 오버레이 위젯이 포함되지 않도록 구조 확인

## Story 2: 반응형 레이아웃 개선 (P0)
**목표:** 모바일/태블릿에서도 쾌적하게 사용할 수 있도록 레이아웃을 개선한다

**현재 상태:** 600px 기준으로 우측/하단 패널 전환은 구현됨. 하단 패널이 고정 240px로 유연하지 않음.

**인수 조건 (AC):**
- AC2.1: 600px 이하 화면에서 패널이 **드래그 가능한 하단 시트**로 전환된다
- AC2.2: 하단 시트는 드래그로 높이를 조절할 수 있다 (접힘/반쯤/완전 펼침)
- AC2.3: 접힌 상태에서도 핵심 액션(박스 추가, 점유율)이 보인다
- AC2.4: 터치 디바이스에서 박스 드래그 시 손가락 오프셋이 적용된다 (손가락 위로 40px)
- AC2.5: 트렁크 캔버스가 사용 가능한 공간에 맞게 동적으로 스케일 조정된다
- AC2.6: 태블릿(600~900px)에서 패널 폭이 적절히 조정된다 (280px→320px)

**기술 노트:**
- `SizedBox(height: 240)` → `DraggableScrollableSheet` 전환
  - `initialChildSize: 0.15`, `minChildSize: 0.10`, `maxChildSize: 0.7`
- 터치 오프셋: `_onPanUpdate`에서 터치 디바이스 감지 시 y 방향 -40px 보정
- 태블릿 분기점: `constraints.maxWidth > 900` → 넓은 패널, `> 600` → 기본 패널

## Story 3: 키보드 단축키 도움말 오버레이 (P1)
**목표:** 사용 가능한 키보드 단축키를 쉽게 확인할 수 있게 한다

**인수 조건 (AC):**
- AC3.1: `?` 키 또는 도움말 버튼 클릭 시 단축키 목록 오버레이가 표시된다
- AC3.2: 오버레이에 현재 사용 가능한 모든 단축키가 카테고리별로 정리된다
  - 카메라: Q(좌회전), E(우회전), 마우스휠(줌), 우클릭드래그(패닝), 0(리셋)
  - 박스: 방향키(이동), R(회전), Delete(삭제)
  - 편집: Ctrl+Z(실행취소), Ctrl+Shift+Z(다시실행)
- AC3.3: 오버레이 밖 클릭 또는 ESC로 닫힌다
- AC3.4: AppBar에 `?` 아이콘 버튼이 추가된다

**기술 노트:**
- `showDialog` 또는 `OverlayEntry`로 구현
- 키보드 이벤트에 `?` (Shift+/) 핸들러 추가
- 반투명 배경 + 중앙 카드 레이아웃

## Story 4: 첫 사용자 온보딩 가이드 (P1)
**목표:** 처음 앱을 여는 사용자가 핵심 기능을 빠르게 이해할 수 있게 한다

**인수 조건 (AC):**
- AC4.1: 박스가 하나도 없는 **빈 상태**에서 캔버스 중앙에 안내 오버레이가 표시된다
  - "박스를 추가하여 트렁크 적재를 시뮬레이션하세요"
  - 화살표로 [+ 박스 추가] 버튼 방향을 가리킨다
- AC4.2: 첫 박스를 추가하면 안내가 자동으로 사라진다
- AC4.3: 빈 상태 안내에 주요 조작법 요약이 포함된다
  - "드래그: 박스 이동 | 우클릭 드래그: 화면 이동 | 마우스 휠: 줌"
- AC4.4: 안내는 세션당 1회만 표시된다 (박스 삭제로 빈 상태가 되어도 재표시 안 함)

**기술 노트:**
- `_showOnboarding` bool 상태 변수 (initState에서 true, 첫 박스 추가 시 false)
- 캔버스 위에 `Positioned` + 반투명 배경 오버레이
- 모바일에서는 조작법 텍스트가 터치 기준으로 변경: "드래그: 박스 이동 | 두 손가락: 화면 이동 | 핀치: 줌"

## 우선순위 & 의존성

```
P0 (필수)              P1 (높음)
──────────             ──────────
S1 (스크린샷 개선)      S3 (단축키 도움말)
S2 (반응형 레이아웃)     S4 (온보딩 가이드)
```

- S1, S2는 독립적, 병렬 진행 가능
- S3, S4는 독립적, S1/S2 이후 진행
- S4는 S2의 반응형 변경을 반영해야 하므로 S2 이후 착수 추천

**추천 순서:** S2 → S1 → S3 & S4 병렬
