# Epic 06: 리얼리즘 렌더링

## 개요

현재 트렁크는 직육면체, 짐은 파스텔 색 블록으로 렌더링된다. 사용자가 "이건 시뮬레이션이 아니라 테트리스"라고 느끼는 근본 원인은 **현실과의 시각적 연결고리 부재**이다.

이 에픽은 두 축으로 리얼리즘을 끌어올린다:
1. **트렁크 형태** — 직육면체 → 실제 차량 트렁크 형태 근사
2. **짐 시각적 정체성** — 색깔 블록 → "아, 이건 캐리어구나" 즉시 인식

**선행 완료:** Epic 01~04, Epic 05 S2(등받이), S4(실루엣)

**핵심 가치:** "테트리스가 아니라 내 차 트렁크에 짐을 싣는 느낌" — 형태와 텍스처로 시뮬레이션 신뢰감을 높인다

**아키텍처 원칙:** CustomPainter + Path 연산으로 구현. 3D 엔진 도입 없이 "모양은 아이소메트릭 근사, 느낌은 텍스처로" 전략.

## Phase 0: Painter 리팩터링 (선행)

### Story 0: Painter 파일 분리 (P0)
**목표:** `isometric_painter.dart` (현재 ~930줄)가 이 에픽 완료 시 1500줄 이상 예상되므로, 책임별로 분리한다

**인수 조건 (AC):**
- AC0.1: `lib/painters/trunk_renderer.dart` — 트렁크 벽/바닥/림/등받이/실루엣 렌더링
- AC0.2: `lib/painters/box_renderer.dart` — 박스 면/그림자/라벨/텍스처 렌더링
- AC0.3: `lib/painters/guide_renderer.dart` — 그리드/치수라벨/스태킹가이드 렌더링
- AC0.4: `isometric_painter.dart` — paint() 오케스트레이션 + 공통 유틸 (toIso, computeCenter 등)
- AC0.5: 기존 56개 테스트 전부 통과, 시각적 변화 없음

**기술 노트:**
- 각 renderer는 `IsometricPainter`의 공개 API (`toIso`, `_projW`, `_projD`, `scale` 등)를 참조
- mixin 또는 별도 클래스로 분리, painter에서 합성
- 순수 리팩터링 — 기능 변경 없음

## Phase 1: 트렁크 형태 리얼리즘

### Story 1: 벽면 테이퍼링 (P0)
**목표:** 트렁크가 뒤로 갈수록 좁아지는 사다리꼴 형태를 표현하여 "자동차 트렁크" 느낌을 준다

**인수 조건 (AC):**
- AC1.1: 트렁크 뒷벽(viewZ=0, 등받이 벽)의 폭이 앞쪽(viewZ=pd)보다 좁게 렌더링된다
- AC1.2: 테이퍼 비율은 차종별로 다르다 (SUV < 세단, 투싼 ~5%, 아반떼 ~12%)
- AC1.3: 바닥도 테이퍼에 맞춰 사다리꼴로 렌더링된다
- AC1.4: 그리드가 테이퍼된 바닥 형태에 맞게 조정된다
- AC1.5: 충돌 감지는 기존 AABB 유지 (시각적 효과만, 내부 박스 공간은 직육면체)
- AC1.6: 4방향 카메라 회전 모두 정상 동작

**기술 노트:**
- `TrunkSpace`에 `taperRatio` 속성 추가 (0.0~0.2, 뒷벽 폭 = w * (1 - taperRatio))
- 차종별 데이터:

| 차종 | taperRatio | 근거 |
|------|-----------|------|
| 투싼 | 0.05 | SUV, 넓은 후방 |
| 쏘렌토 | 0.04 | 대형 SUV |
| 싼타페 | 0.04 | 대형 SUV |
| 카니발 | 0.03 | 미니밴, 거의 직사각 |
| 아이오닉5 | 0.06 | EV, 약간 좁아짐 |
| 아반떼 | 0.12 | 세단, 뒤로 갈수록 많이 좁아짐 |

- painter에서 뒷벽 꼭짓점을 `x ± (w * taperRatio / 2)` 만큼 안쪽으로 이동
- 바닥 Path도 동일하게 사다리꼴화
- **충돌 감지는 변경 없음** — 시각적 테이퍼 안쪽에도 박스 배치 가능 (실제 차량도 벽 바로 옆까지 넣을 수 있음)

### Story 2: 휠하우스 곡면화 (P0)
**목표:** 직육면체 휠하우스를 실제 차량처럼 둥근 형태로 표현한다

**인수 조건 (AC):**
- AC2.1: 휠하우스 상단 모서리가 `quadraticBezierTo`로 둥글게 표현된다
- AC2.2: 휠하우스와 바닥 접합부에 부드러운 필렛(곡면 이음)이 추가된다
- AC2.3: 휠하우스 측면(벽 쪽)에 약간의 경사가 표현된다 (위로 갈수록 안쪽으로)
- AC2.4: 충돌 감지는 기존 AABB 유지 (곡면은 시각적 효과만)

**기술 노트:**
- `_drawIsometricBox()` 대신 전용 `_drawWheelhouse()` 메서드 생성
- 상단면: 모서리 4개에 `quadraticBezierTo` 라운딩 (반경 ~3cm)
- 측면: 상단이 하단보다 약간 좁은 역사다리꼴
- 바닥 접합 필렛: 바닥-벽 코너에 삼각형 또는 쿼드 베지어 곡면 추가

### Story 6: 카테고리별 텍스처/아이콘 렌더링 (P0)
**목표:** 짐 종류를 한눈에 구별할 수 있는 시각적 힌트를 박스 표면에 렌더링한다

**인수 조건 (AC):**
- AC6.1: **캐리어** — 윗면에 바퀴 도트(4개) + 옆면에 손잡이 라인
- AC6.2: **이사박스** — 윗면에 테이프 십자 라인 + 옆면에 "📦" 또는 텍스트 힌트
- AC6.3: **캠핑** — 윗면에 X자 스트랩 패턴 + 옆면에 버클 도트
- AC6.4: **커스텀** — 현재처럼 솔리드 컬러 (텍스처 없음)
- AC6.5: 텍스처는 박스 색상에 대해 반투명 오버레이로, 어떤 색상에서든 잘 보인다
- AC6.6: 줌 아웃 시 텍스처가 너무 작으면 자동으로 숨김 (가독성 유지)

**기술 노트:**
- `box_renderer.dart`에 카테고리별 `_drawBoxTexture()` 분기
- 캐리어 바퀴: 윗면 4 코너에 `canvas.drawCircle()` (색상의 30% 어두운 톤)
- 캐리어 손잡이: 옆면 상단에 수평 라인 + 작은 사각형
- 이사박스 테이프: 윗면 중앙 십자 (색상의 20% 밝은 톤, 반투명)
- 캠핑 스트랩: 윗면 X자 대각선 라인 (색상의 25% 어두운 톤)
- 텍스처 표시 조건: 윗면 아이소 투영 폭 > 30px

## 우선순위 & 의존성

```
Phase 0 (선행)          Phase 1 (형태)           Phase 2 (짐)            Phase 3 (분위기)
──────────────         ──────────────          ──────────────         ──────────────
S0 (Painter 분리) ──┬── S1 (벽면 테이퍼링)      S5 (카테고리 모델) ──── S6 (텍스처)    S8 (내장재)
                   ├── S2 (휠하우스 곡면)                           S7 (색상 팔레트) S9 (라이팅)
                   ├── S3 (트렁크 립)                                               S10 (하이라이트)
                   └── S4 (바닥 단차)                                               S11 (바닥 로고)
```

**의존 관계:**
- S0 → 모든 Phase 1~3 스토리 (분리 후 작업)
- S5 → S6, S7 (카테고리 모델 있어야 텍스처 적용 가능)
- Phase 1, Phase 2는 독립적으로 병렬 진행 가능
- Phase 3은 Phase 1 이후 진행 추천 (형태 위에 분위기 적용)

**추천 구현 순서:** S0 → (S1 + S5 병렬) → S2 → S6 → S3 → S7 → S9 → S8 → S4 → S10 & S11

## 핵심 설계 원칙

1. **"형태는 근사, 느낌은 텍스처로"** — 3D 엔진 없이 CustomPainter Path 연산으로 최대한 현실감 달성
2. **충돌 감지 불변** — 테이퍼/곡면 등 모든 시각적 변경은 기존 AABB 충돌 감지에 영향 없음
3. **짐은 여전히 직육면체** — 비정형 형태는 구현 비용이 과도하므로, 표면 텍스처로 정체성을 표현
4. **점진적 향상** — Phase별로 독립 배포 가능, 각 Phase만으로도 체감 효과 있음
